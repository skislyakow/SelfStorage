# Конвенции проекта

Единое место договорённостей, чтобы 3 разработчика не конфликтовали по именам адресов, данным шаблонов и сигналам между приложениями. Любое изменение — через правку этого файла.

## 1. Реестр имён URL

Имена задаются через `name` в `path(..., name="...")`. Префикс совпадает с приложением.

| `home` | Главная | (project) | — |

## 2. Переменные контекста шаблонов

Каждая view обязана передавать в шаблон перечисленные переменные (имена фиксированы).

### `warehouses:list`
- `warehouses` — список складов.
- Для каждого склада ожидаются поля: `name`/город+адрес, `address`, `photo`, `free_count` (число свободных боксов), `total_count` (общее число боксов), `min_price` (минимальная цена), `feature` (особенность склада).

### `warehouses:detail` (`pk`)
- `warehouse` — объект склада.
- `boxes` — боксы склада с фильтрами (площадь/этаж/цена).

### `boxes`
- `boxes` — отфильтрованный список боксов.
- `filters` — текущие значения фильтров.

### `rentals:wizard`
- `steps` — число шагов (4).
- `current_step` — текущий шаг.
- `box` — выбранный бокс (шаги 2–4).
- `form` — форма текущего шага.
- `summary` — сводка цен (с учётом промокода).

### `profile:my_rent`
- `orders` — аренды пользователя.
- Для каждого заказа: `items_text` (список вещей) ИЛИ `area`+`period` (площадь и период), `qr_code` (URL/путь к qr.png), `status`.

### `owner:panel`
- `deliveries` — заявки на доставку с `client_address`, `phone`, `status`.
- `overdue_orders` — просроченные заказы с телефонами владельцев боксов.

## 3. Сигналы между приложениями

Объявляются в `apps.<app>/signals.py`, подключаются в `apps.<app>/apps.py::ready()`.

| сигнал | sender | когда | подписчик / действие |
|---|---|---|---|
| `order_created` | `RentalOrder` | создан заказ | notifications: письмо подтверждения; payments: создать платёж |
| `payment_succeeded` | `Payment` | успешный платёж | rentals: перевести заказ в `active`, освободить бронь |
| `order_overdue` | `RentalOrder` | истёк срок | notifications: письмо о просрочке и тарифе 6 мес |

## 4. Прочее

- Логин пользователя — `email` (`AUTH_USER_MODEL = apps.users.User`).
- Вычисляемые значения («14 из 390», «от 3034 ₽») не храним в БД — считаем на лету.
- Почта в разработке — консоль (`EMAIL_BACKEND = console`).

## 5. Команды управления

| Команда | Описание | Где лежит |
|---------|----------|-----------|
| `send_notifications` | Отправляет напоминания об окончании аренды, обрабатывает просрочки | `apps.notifications.management.commands` |

### Логика работы `send_notifications`

1. **Напоминания за 30/14/7/3 дня** — находит активные заказы, у которых дата окончания = сегодня + N дней, отправляет письмо.
2. **Перевод в просрочку** — находит активные заказы, у которых дата окончания < сегодня, меняет статус на `overdue`.
3. **Ежемесячные напоминания** — для заказов со статусом `overdue` проверяет, сколько дней прошло. Если количество дней кратно 30, отправляет письмо.
4. **Потеря вещей через 6 месяцев** — для заказов со статусом `overdue` и датой окончания ≥ 180 дней назад меняет статус на `finished` и отправляет финальное предупреждение.

### Письма (email-шаблоны)

| Тип письма | Когда отправляется | Функция |
|------------|---------------------|---------|
| Напоминание об окончании | За 30/14/7/3 дня до окончания | `send_reminder(order, days_left)` |
| Просрочка | Сразу после истечения срока | `send_overdue_reminder(order, days_overdue)` |
| Ежемесячное напоминание | Каждые 30 дней просрочки | `send_overdue_reminder(order, days_overdue)` |
| Финальное предупреждение | Через 6 месяцев просрочки | `send_final_warning(order)` |
