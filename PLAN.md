# План реализации 

## 1. Что делаем

Минимальный работающий вариант сервиса аренды складских боксов по техническому заданию: главная страница на основе готовой вёрстки (папка layot/, берём как есть), каталог складов и боксов, заказ с доставкой, личный кабинет, напоминания по электронной почте, доступ по QR-коду, промокоды, платёжная система ЮKassa (тестовый режим), учёт источников рекламы, панель управления для владельца.

Команда: три разработчика, всего шесть рабочих дней. Рабочие дни — вторник–воскресенье, понедельник — выходной. Чтобы работать параллельно без конфликтов, в первый же день фиксируем общие договорённости: какие имена адресов используются, какие данные передаются в шаблоны и какие сигналы посылаются между приложениями.

Режим работы и календарь: весь проект укладывается в шесть дней подряд со вторника по воскресенье, понедельник — выходной. Окно плотное, поэтому часть задач (стеллажи для юридических лиц, консультант Jivo, расширенная аналитика) при необходимости упрощается до заглушек и докручивается после показа заказчику. Старт — во вторник. Раскладка задач по дням — в разделе 7.

## 2. Стек технологий 

| Компонент | Выбор |
|---|---|
| Язык и фреймворк | Python + Django  |
| База данных | SQLite (файл, не требует настройки) |
| Окружение | виртуальное окружение venv + файл requirements.txt, запуск через python manage.py runserver |
| Конфигурация | `django-environ`; настройки (SECRET_KEY, DEBUG, ALLOWED_HOSTS, EMAIL_BACKEND, YOOKASSA_*) берутся из `.env`. Шаблон — `.env.example` в репо; локально нужен `.env` с `DEBUG=True`, `ALLOWED_HOSTS=127.0.0.1,localhost`. |
| Рассылки по расписанию | встроенная команда управления (send_notifications) — вручную при отладке либо по расписанию через cron или Планировщик заданий Windows на демонстрации |
| Почта в процессе разработки | вывод писем в консоль (письма печатаются в терминал), настоящая отправка подключается одной настройкой позже |
| Оплата | библиотека ЮKassa, сначала тестовые ключи |
| QR-коды | библиотека qrcode |
| Онлайн-консультант | виджет Jivo, одна строка в шаблоне |
| Демонстрационный запуск | VPS Ubuntu, `gunicorn` + `nginx`, домен `https://selfstorage.kislyakov.pro` (HTTPS через certbot, http→https); ветка `main` автодеплоится через GitHub Actions → SSH (`bash deploy.sh`). Демо-аккаунты для входа — в README. |



### Порядок запуска (подход владельца)

Последовательный «позвоночник» старта:

1. Первый день — пустой проект и хранилище кода. Каркас Django, пустые приложения, файл .gitignore, README, репо → ссылка команде.
2. Дни 1–2 — модели по вёрстке. Данные выводим из папки layot/ и из сценариев технического задания (вёрстка не показывает статусы, просрочки, промокоды). Вычисляемое («14 из 390», «от 3034 ₽») не храним — считаем на лету.
3. Дни 2–3 — вёрстка на базовый проект. Сначала один общий шаблон base.html (шапка, подвал, модальные окна), потом 5 страниц; данные для примеров берём из фикстур.
4. Дни 3–6 — функции по одной из списка задач раздела 7: сверху вниз, каждая функция = готовый к показу шаг.

С самого начала фиксируем общие договорённости в одном месте: какие имена адресов используются, какие данные передаются в шаблоны и какие сигналы посылаются между приложениями. Заполняем их параллельно с шагами 2–3, иначе на шаге 4 три разработчика столкнутся по именам адресов и данным шаблонов.

## 4. Модели данных

- Пользователь (User) — электронная почта (логин), телефон, дата принятия согласия на обработку персональных данных
- Склад (Warehouse) — город, адрес, фото, температура, высота потолков, описание, контакты
- Бокс (Box) — склад, номер, этаж, площадь, габариты длина×ширина×высота, цена в месяц, статус
- Заказ аренды (RentalOrder) — пользователь, бокс, даты начала и конца, список вещей (текст), статус: awaiting_payment → active → overdue → extended_6m → finished, промокод, сумма, метка источника трафика
- Заявка на доставку (DeliveryRequest) — заказ, адрес клиента, телефон, статус («куда ехать» для доставщика)
- Промокод (PromoCode) — код, процент скидки, период действия (storage2022 = март; storage15 = ноябрь–апрель)
- Платёж (Payment) — идентификатор платежа ЮKassa, статус, сумма

## 6. Покрытие сценариев технического задания и рисков

- Узнавание сервиса → главная страница с примерами использования ✅
- Правила хранения / разрешённое и запрещённое → отдельная страница ✅
- Заказ: адреса складов + бесплатная доставка + цены по объёму + «замерим сами» ✅
- Напоминания об окончании аренды за 30 / 14 / 7 / 3 дня ✅
- Просрочка: 6 месяцев повышенный тариф → ежемесячные письма → предупреждение о потере ✅
- Забор вещей → QR-код + адрес (+ сценарий «забрать часть и вернуть») ✅
- Согласие на обработку персональных данных → чекбокс + запись даты + PDF ✅
- «Сколько людей сделали заказы с рекламы» → учёт меток источника трафика + отчёт ✅
- В панели управления видно «куда ехать» и телефоны клиентов ✅
- Риски дизайна/интерфейса → вёрстка готова, берём как есть ✅
- Риски доставки («не поместится», «не пройдут условия») → поля отказа у доставщика ✅
